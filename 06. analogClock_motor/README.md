# 06. analogClock_motor

스텝모터 3개로 **시침·분침·초침**을 움직이는 아날로그 시계입니다.
05번의 RTC 시계 / 스톱워치를 바탕으로, 바늘 위치를 시간에 맞춰 계속 따라가게 만들었습니다.

## 동작

| 버튼 | 동작 |
|---|---|
| PC0 | 시계 ↔ 스톱워치 모드 전환 |
| PC1 | (스톱워치) Run / Stop |
| PC3 | (스톱워치) Stop 상태에서 Clear (Run 도중 실수로 초기화되는 것 방지) |

- 시계 모드: 바늘이 현재 시간을 가리킴, LCD에 시간과 날짜 표시
- 스톱워치 모드: 바늘이 스톱워치 시간을 가리킴, LCD 2행에 `SW:HH:MM:SS:ms`
- 모드를 바꾸면 바늘이 새 시간으로 빠르게 이동

## 하드웨어

| 장치 | 연결 |
|---|---|
| 28BYJ-48 스텝모터 (초침) | PA0, PA1, PA4, PB0 |
| 28BYJ-48 스텝모터 (분침) | PC10, PC11, PC12, PD2 |
| 28BYJ-48 스텝모터 (시침) | PC9, PC8, PC6, PC5 |
| DS3231 RTC, 16x2 I2C LCD | I2C1 |

> 첫 전원 투입 시 바늘이 12시에 있다고 가정하므로, 손으로 12시에 맞춰 두어야 합니다.

## 타이머 설정

| 타이머 | 주기 | 용도 |
|---|---|---|
| TIM2 | 1ms | 스텝모터 3개 구동 (`StepMotor_task`) |
| TIM3 | 1ms | FND / 화면 갱신 (`Disp_ISR`) |
| TIM4 | 10ms | 시계·스톱워치 시간 증가 |

스텝 구동을 메인 루프가 아니라 **TIM2 인터럽트**에서 하는 이유: LCD 출력(I2C) 때문에 메인 루프가 느려서 스텝이 끊기기 때문입니다.

## 설계할 때 고민한 점

### 1. 바늘을 빠르게 따라잡기
시계 시간은 모드와 상관없이 계속 흐릅니다. 스톱워치에서 시계로 바꿨을 때 시계 방향으로만 따라가면, 목표가 바로 뒤(예: 59초)일 때 거의 한 바퀴를 돌아야 합니다.

- 현재 위치와 목표 위치의 차이가 **반 바퀴(2048스텝)보다 크면 반시계 방향**으로 회전 → 이동 거리가 항상 반 바퀴 이하
- 목표와 1초 이상 차이 나면 2ms/스텝으로 빠르게, 따라잡은 뒤에는 10ms/스텝으로 평소 속도

### 2. 스텝 오차 보정
한 바퀴는 하프스텝 기준 **4096스텝**이라 60(초·분)이나 12(시)로 나누어 떨어지지 않습니다. 1초마다 정수 스텝을 더하면 소수점 오차가 쌓입니다.

- 매번 **누적 시간 전체를 스텝 위치로 다시 계산**
  `목표 스텝 = 누적 시간 × 4096 ÷ 한 바퀴 시간`
- 버림 오차가 쌓이지 않아 바늘 위치가 항상 1스텝 안으로 유지됨

### 3. 아날로그 시계다운 움직임
디지털 단위로만 움직이면 바늘이 뚝뚝 끊깁니다. 바늘마다 한 단계 아래 단위까지 반영했습니다.

| 바늘 | 반영 단위 | 계산 |
|---|---|---|
| 초침 | 10ms | `(초×100 + 10ms) × 4096 / 6000` |
| 분침 | 초 | `(분×60 + 초) × 4096 / 3600` |
| 시침 | 분 | `((시%12)×60 + 분) × 4096 / 720` |

## 스텝모터 드라이버 (`driver/stepmotor`)

- 하프스텝 패턴 8개: `0x01, 0x03, 0x02, 0x06, 0x04, 0x0C, 0x08, 0x09`
- `StepMotor_setTarget()`: 목표 위치만 정함
- `StepMotor_task()`: 1ms마다 호출, 목표 쪽으로 한 스텝씩 이동 (블로킹 없음)
- 이동 중에는 코일 전원을 끄지 않아 스텝을 놓치지 않음
- 모터마다 `stepMotor_t` 구조체(핀, 현재 위치, 목표)를 따로 가져서 같은 코드로 3개를 구동

## 디버깅

메인 루프에서 1초마다 UART로 다음 값을 출력합니다 (`[DEBUG]` 표시된 코드).
루프 최대 시간, 1초 동안 TIM2 인터럽트 횟수, I2C 에러 코드와 상태
